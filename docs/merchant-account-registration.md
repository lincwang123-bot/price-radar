# 商家注册与联系资料

浏览报价、游客本机关注不要求注册。注册必须验证邮箱、设置密码，填写手机号及微信/TG/QQ 中一项联系账号。手机号只做格式检查，不发送短信、不标记号码归属已验证。大陆手机号规范化为 `+86`，海外号码须带国家区号。

`/submit-shop` 和 `/api/merchant-applications` 都要求有效登录会话、已设置密码和完整联系资料。旧账号未设置密码时引导注册/首次设置；缺少联系资料时引导 `/account?next=...`，保存后返回提交店铺。登录跳转仅允许现有站内业务路径。账号注册和补资料不会自动批准店铺，也不产生管理员权限。

新申请的邮箱取已登录账号的验证邮箱，手机号和联系渠道取私有账号资料，忽略请求体伪造的联系方式及账号 ID。新申请保存提交账号 ID 和联系资料快照。后台审核可查看手机号，但公开目录、收录清单、报价和排查复制文案不包含这些字段。历史申请不会根据邮箱自动绑定账号，后台人工整理供应投稿仍保留原有受审核流程。

资料保存在私有 SQLite 的 `reader_profiles`；`merchant_applications` 增加可空的 `applicant_account_id`、`phone`，迁移可重复执行，保留历史记录。账号详情可更新联系资料；`POST /api/retention/profile` 复用登录、同源、CSRF 和频率控制。资料不进入公共 state 响应、URL、浏览器持久存储、日志或统计。删除账号会清除账号资料，申请中的历史联系快照按店铺申请政策保留，隐私页明确说明。

部署前备份私有数据库。无短信供应商、短信密钥或新增费用。验证包括服务端注册校验、匿名提交拒绝、旧账号补资料、伪造联系数据、会话失效、删除资料，以及桌面/手机端注册和返回提交页。浏览器测试使用隔离数据库与模拟邮件，不给真实商家发送测试消息。
