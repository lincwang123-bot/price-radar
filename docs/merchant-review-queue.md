# 店铺审核队列

`/admin/merchants` 将正式申请与未转为正式申请的供应投稿合并，按原提交时间从新到旧排序。状态数量和每页 30 条的分页都按合并后的记录计算；供应投稿不再固定占据列表顶部。

- 待审核卡片中的“填写意见 · 拒绝 / 暂存”可以填写内部意见，选择“拒绝申请”或“移到暂存”。详情页也提供相同入口。
- 拒绝后进入“已拒绝”；暂存进入“暂存 / 暂停”。该分类也保留原有暂停采集的正式店铺。
- 已拒绝或暂存的记录可以恢复待审核。恢复会增加版本号，旧检测结果不能用于批准，需重新检测和审核。
- 上述队列操作不生成邮件。内部意见、操作人、时间和状态变化保留在审核记录，原供应投稿内容保留。
- 已经转为正式申请的投稿不重复出现在队列中，只能在正式申请中处理。拒绝或暂存的投稿必须先恢复，才能转为正式申请。重复导入不会重置其处理状态。

供应投稿新增 `merchant_supply_intake.status / version / updated_at`，旧记录默认 `pending / 1`，无批量处理旧申请。`merchant_intake_actions` 是只追加的处理记录；正式申请继续使用现有审核记录表。

部署前备份私有 SQLite 数据库。先更新运行文件并重启 Web 服务完成兼容迁移，再重启采集和接入测试服务。回滚运行文件时保留新增数据及处理记录，不能用旧数据库覆盖运行期间的新申请。
