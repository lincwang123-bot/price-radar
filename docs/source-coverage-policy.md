# 原店覆盖验收

历史报告做过 33/45 产品、245/223 报价、21/108 店名的样本对照；这些计数不是同 SKU 覆盖率。本工具按当前公共报价策略重新比较 PriceAI **公开样本**与独立直采，不能验证 PriceAI 未公开的全站报价。

## 运行

`node scripts/source-coverage.mjs --db /absolute/path/radar.sqlite --json`

加 `--report /absolute/path/new-report.md` 可导出新报告（拒绝覆盖已有文件）；加 `--record /absolute/path/source-coverage-ledger.json` 写每日验收记录。行情 SQLite 只读。现有 `runPull` 每轮结束自动调用相同记录器，记录到数据目录 `source-coverage-ledger.json`；记录失败不会使已完成采集失败。不新增守护进程、抓取或自动关源。

## 可比范围与门槛

- 经已测试的原店标题分类器确认的规范产品 ID 和 `comparison_key`（期限、档位、交付、地区、单位、币种），再区分标题中明确的全程/时长质保与未注明保障；采用公共售罄、明确无保障、有效正价、新鲜度过滤。
- 目录 ID 不同或规格信息不足不臆断等价；这可能少算真实覆盖，但不会把不确定商品作为替代证据。
- PriceAI 快照 stale、失败、缺少源生成时间、源生成时间超过 60 分钟时，结果为“不可判定”，覆盖率 `null`。本地刚抓取不能重置旧源数据年龄。
- 覆盖要求每个可比基准组有至少一个不同原店域名；停用建议还要求直采最低价不高于基准，并且无未解决规格组。
- 连续至少 7 个不同 UTC 日期、相同基准范围、每日有效且全部通过，才输出 `eligible_for_manual_review`。只建议人工核对必要品类、旧链接及提醒迁移后停用，绝不自动关闭 PriceAI。
- 每日保留最新样本以及“当天全部有效评估是否通过”、观察次数和不可判定次数；同快照同状态重复运行不追加。当天最初数据不足、后来取得有效对照可以恢复；但当天曾出现有效对照失败，后续瞬时通过不能抹掉失败。最新采样不可判定也会撤回当天通过状态。最多保留 90 天。每日成功采样不代表 24 小时全时段可用。

新店接入证据单独写入 `source-coverage-expansion.md`；未实际通过公开目录验证的候选不得默认启用。
