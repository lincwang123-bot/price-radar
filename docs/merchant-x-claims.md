# 店主 X 认领与店铺分享

现有报价已经带来一些店铺申请和订单反馈。本功能让店主主动说明店铺对应的公开 X 账号，同时获得可分享的店铺页；它本身不能证明信誉，也不能保证用户回访或 X 传播效果。

## 店主流程

1. 从报价旁点击「我是店主 · 认领 X 账号」，或打开 `/claim-shop?new=1` 搜索已收录店铺。未收录者仍走 `/submit-shop`。
2. 填写可控制的 X 账号、联系邮箱，确认有权代表店铺并同意公开关联。
3. 保存专属进度链接；认领码 7 天内有效。把认领码与店铺网址放入自己的 X 帖子或个人简介，然后提交证明位置、店铺核验链接（选填）及归属说明。
4. 等待站长审核，通过专属进度链接查询结果。此链接含随机查询凭据，不可公开；本站暂不自动发送认领结果邮件。
5. 审核通过后，在报价和独立店铺页显示 `X @username`。可点击分享按钮前往 X 自行编辑和发布。

公开发帖可选；选择简介证明同样可以申请。认领码是公开的关联证明，不是 X 登录验证码。分享功能使用 [X Web Intent](https://docs.x.com/x-for-websites/web-intents/overview)，没有 OAuth 授权、自动发帖或嵌入式第三方组件。

## 站长审核

使用已有管理员账号访问 `/admin/x-claims`。只有店主提交了证明的申请进入待审队列。

- 打开申请人对应的 X 账号，核对真实页面中的认领码、账号和店铺网址。提交了链接不等于验证成功。
- 独立核对店铺归属：店内公告、联系页或可证实的人工联系记录。控制一个 X 账号不等于有权代表店铺。
- 两项检查均完成后，勾选确认并记录具体核验依据，再点击「通过并展示 X」。内部依据只在后台显示；「给认领人的说明」只在其专属进度页显示。
- 已有账号时需额外确认替换；旧关联转为撤销并保留记录。账号变更、归属争议可撤销展示，保留原报价与店铺页面。

不能只凭简介、粉丝数、账号认证标识或申请人自述认定店铺控制。人工审核无法保证未来账号不转让、不被盗或店铺始终可靠；用户界面明确说明关联的含义。

## 报价排序

产品报价页默认使用综合排序：在同一币种内，X 已关联店铺优先，其次为店铺已收录，最后为其他店铺；同类按价格从低到高。用户可切换为纯价格升序或降序，切换排序保留交付方式、平台、规格和币种筛选，并回到第一页。撤销关联或暂停收录后，下次页面请求立即使用最新状态。

排序只作用于经过有效性过滤、去重后的报价，不增加或隐藏店铺，不影响首页最低价、报价数量或参考报价。标识不代表信誉评级或交易担保，广告仍在独立区域展示。

## 数据与边界

`merchant_x_shops`、`merchant_x_claims`、`merchant_x_actions` 保存在现有私有 `submissions.sqlite`，沿用文件权限、每日及异机备份。启动时自动创建新增表，不改动既有商家申请、采集授权、历史价格、关注或邮件队列。

店铺标识由现有 merchant identity 确定：独立站使用精确域名；共享平台必须由本站采集器给出精确店铺信息，不能把整个平台认领成一家店。公开报价变化后，已登记店铺页仍保留关联信息，暂时没有有效报价时如实显示。

公开页面只读取已批准的账号关联。私人进度接口使用随机 256 位凭据、数据库仅存凭据摘要，凭据通过 URL fragment / POST body 传输；不进入分享链接、日志查询参数或搜索索引。联系邮箱只供核验，未经认领同意不会从旧私有投稿自动提取 X 账号。

提交使用现有同源验证、CSRF、请求大小限制。每 IP 摘要每小时最多 3 次、每日最多 5 次；每联系邮箱每日最多 5 次；总申请每日最多 150 次。IP 用持久化 `SUBMISSION_HASH_SECRET` 做 HMAC，不存原地址。后续申请触发清除 48 小时以前的限流摘要及超过 7 天的未提交草稿。已提交资料与审核记录用于维护、争议处理；人工处理更正/删除请求，历史灾难恢复备份按既有策略保留。

管理员审核需现有登录会话、CSRF 和版本匹配；批准、拒绝、替换、撤销采用事务及追加审核记录。同一店铺最多一个已批准账号。公开店铺页可索引，canonical 保留店铺 ID；认领、进度、API 和管理页不索引。

## 验证

`npm run check` 包含账号和链接规范化、共享平台隔离、申请限流和过期、进度凭据、同源/CSRF、管理员审批、显式替换、撤销、版本冲突、审核记录不可改写，以及报价页/店铺页不泄漏联系邮箱和私密凭据的测试。浏览器实测使用合成店铺、合成邮箱和本地管理员，覆盖桌面与手机；不向 X 或真实邮箱发测试消息，不在生产库创建虚假认领。
