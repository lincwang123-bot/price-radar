# 店铺自动检测与邮件通知

## 站长操作

- 新申请：通知邮箱必填。提交后，Web 进程每 15 秒同步检测队列；现有采集进程通常每 5 分钟处理一轮、每轮最多 2 家。测试只读公开目录，不会批准或发布报价。
- 后台「店铺审核」同时显示正式申请和已转入的供应投稿。供应投稿是待核对线索，不替申请人确认归属或采集授权。原始记录、联系人不变。
- 单个合法公开网址自动检测。多个网址拼接、格式错误不发起请求；已存在申请的显示关联候选，不合并联系人。核对资料后通过原有转申请表单确认店名、归属及授权。
- 旧投稿只有当整个联系方式字段就是一个合法邮箱时才沿用，否则显示「待补邮箱」。可在详情页补齐邮箱，必须确认来自当前申请人；无邮箱不能在 HTTP 审核入口批准。
- 审核仍需要人工确认店铺归属、采集权限、样例价格和规格。自动检测成功不代表交易可信。
- 通知补资料、批准、拒绝或暂停使用统一绿白品牌 HTML 模板，并附完整纯文本版本。后台「发给用户的回复」会进入邮件；「内部备注」始终不外发。也可以仅回复而不改变审核状态。
- 反馈与供需表单支持独立的可选通知邮箱；有有效邮箱才发送提交回执、处理结果和站方回复。匿名反馈继续可用。供应线索优先使用后台确认的通知邮箱，不修改原始联系方式。
- 提交回执、明确回复不会被新阶段覆盖；上架也不会覆盖审核通过通知。其他尚未发送的旧阶段可以被最新进度替代。重复操作相同事件不重复入队，同状态下 5 分钟内的相同回复去重。
- 上架通知要求：已批准、审核后的成功采集、精确店铺身份、已落库的最新直采快照，且通过与公开目录相同的有效报价过滤；售罄、无保障、过期或仅有接入测试结果不会触发。每次批准周期只通知一次。
- 后台邮箱为非链接明文，认证、CSP、禁止缓存保持不变；仅后台响应增加 `Cache-Control: no-transform`，阻止边缘邮箱混淆把地址改成保护页链接。

## 配置发件邮箱

需要站主先指定发件服务与邮箱。不要在聊天、Git 或普通日志中提供密码。
由管理员在生产 `/etc/price-radar/web.env`（root:root 0600）安全填写：

```dotenv
MERCHANT_MAIL_FROM=notify@your-domain.com
MERCHANT_MAIL_REPLY_TO=hello@your-domain.com
MERCHANT_SMTP_HOST=smtp.your-provider.com
MERCHANT_SMTP_PORT=465
MERCHANT_SMTP_USER=your-provider-user
MERCHANT_SMTP_PASSWORD=your-provider-app-password
```

端口仅允许 465（隐式 TLS）或 587（必须 STARTTLS）；不关闭证书验证。使用服务商授权码或应用密码，不使用个人邮箱登录密码。按服务商要求配置 SPF、DKIM、DMARC，然后重启 Web 服务并用站主指定的测试收件箱做实发验收。

SMTP 实现参考 [Nodemailer 官方文档](https://nodemailer.com/smtp)。依赖锁定在 package-lock.json；生产需要 `npm ci --omit=dev --ignore-scripts`。

Resend 可使用 `smtp.resend.com:587`、用户名 `resend`，密码为域名受限、仅发送权限的 API key；域名必须先验证。配置 Reply-To 前先确认收件转发真正可用。Resend 请求附稳定幂等键。完成 SMTP 到指定测试收件箱的实发验证前，不能把模板测试或 Gmail 样式预览称为网站发件验收。

## 队列与失败口径

- 未配置：保留队列，后台明确提示，不调用网络、不显示已发送。
- SMTP 接受：仅显示「发送服务已接受」，不能解释为进入收件箱、已读或保证送达。尚未接入退信回调。
- 每轮最多 3 封；同一事件幂等、单收件人每日最多 20 个尝试过的通知事件；公开申请每邮箱每天最多 5 次，原 IP 限流继续生效。
- 连接失败有上限的指数退避，最多 4 次；认证或拒收错误停止自动重试。
- SMTP DATA 阶段中断、未知异常或发送中进程退出，标记结果不确定，不自动重发。SMTP 不提供端到端 exactly-once 保证。需查服务商记录后人工处理。
- 不记录 SMTP 原始异常文本、凭据、内部审核说明；持久化错误码仅用于后台提示。
- 关闭服务时停止调度，等待当前有时限的发送尝试结束后再关闭私有数据库。

## 指定旧投稿导入

先用 SQLite 在线备份并验证恢复，再运行：

```sh
node scripts/import-supply-intakes.mjs /absolute/path/submissions.sqlite CO-id-1 CO-id-2
```

脚本幂等、事务写入，不删除投稿，不批准店铺。只处理明确提供的 1–100 条 supply ID；任何 ID 不存在或不是 supply 时整批回滚。通知状态、原始投稿和转入记录都在同一个私有库里，随现有整库备份保存。
