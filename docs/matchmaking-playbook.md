# 供需撮合：先人工验证，再产品化

更新：2026-09-07。本文是运营建议，不是已上线收费功能，也不构成具体法律意见；正式收费前应结合经营主体、合同与税务情况由专业人士核对。

## 目前有什么

网站已有供方/采购方提交入口，后台可查看、分类、修改处理状态并保存内部备注。现有“已采纳”不是“已成交”；还没有自动匹配、成交核验、佣金结算或支付系统。现有广告区与自然报价排序分开。

现有提交同意仅涵盖有权提交及没有敏感凭据，不能当作同意把联系方式分发给供方。线索不自动公开，也不自动联系第三方。

## 建议工作流程

`收到线索 → 核实需求与供方 → 明确委托及收费 → 同规格询价 → 单独同意对接 → 双方直接交易 → 跟进交付及服务费`

1. **核实需求**：确认采购主体、产品/档位、使用地区、账号归属、数量/人数、周期、预算、交期、发票、保障和退款要求。一次补齐关键选项，不反复让对方写长说明。
2. **核实供方**：确认经营主体、供货来源/授权、可交付量和日期、售后范围与证据。店主核验不等于供货授权或交易担保，不收账号密码、卡密或原始 API Key。
3. **确定委托**：先约定站点要做什么、由谁付费、价格或计算方法、何时算完成、终止/退款条件。没有确认付费意愿就不要投入大量询价工时。
4. **同规格比较**：向 2–3 家合适供方发送不含个人信息的需求摘要，记录含税总价、单位、报价有效期、测试条件和保障。共享/独享账号、企业席位、代充和 API 应用分别比较，不能只比一个最低价。
5. **双方同意后介绍**：明确具体接收方、目的、分享字段及方式，记录各方单独同意后才发送联系方式；不把原表单整份转发。[个人信息保护法第 23 条](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)
6. **直接签约付款**：在产品条款允许的前提下先小额测试，由采购方与供方直接签约、付款。站点暂不代收货款、不做托管或履约担保。
7. **确认与结算**：记录合同/订单、付款、交付和争议情况，达到事先约定的服务验收或成功费条件后结算。点击链接、加好友、后台“已采纳”都不能作为成交依据。

## 可以在哪里收费

| 模式 | 交付和付费对象 | 初期建议 |
| --- | --- | --- |
| 采购筛选服务费 | 向委托采购方交付需求梳理、可核对的比较结果及风险说明 | 先确认实际独立服务和验收标准；不能把未成交佣金改名收费 |
| 成功费 | 向事先约定的一方收撮合报酬，固定金额或透明计算方式 | 有可核对成交依据；可约定付款且测试确认后结算，避免仅凭跳转计佣 |
| 广告费 | 向广告主收展示位置和期限费用 | 显著标注“广告”，与价格排序及核验标识分开，不承诺虚构点击或成交 |

民法典中介合同规则要求如实报告；未促成合同原则上不得请求报酬，但可按约请求必要费用。具体业务不能只看收费名称，应看实际服务性质和合同。[民法典第 961–966 条](https://gongbao.court.gov.cn/Details/7f184078694d811fb3314f6af9accf.html)

广告不能包装成客观推荐或付费买认证；中文页面应清晰标注“广告”。[市场监管总局广告可识别性指南](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2024/art_89824524f2804c5594e95408fbdf8602.html)

不建议靠卖联系方式、隐瞒双向佣金、收钱就标“已核验”、付费抬高自然排名赚钱。隐瞒价差也会损害导航站的可信度。

## 收入不等于利润

先试跑 **5 单**（这是建议样本量，不是已有成交数），记录实际工时、成交率、实收、退款和复购意愿。没有这些数据前，不宜编定价或利润预测。

`单笔贡献 = 实收服务费 + 实收成功费 − 获客成本 − 服务工时 × 内部小时成本 − 退款/争议处理成本 − 支付/开票等变动成本`

`周期经营利润 = 各单贡献合计 + 广告贡献 − 固定运营成本`

建议第一阶段选需求明确、采购量较大且愿意为筛选付费的客户；小额零售是否值得人工对接，要由单笔工时验证。不要同时收取重复服务的两笔费用。

## 后台下一步需要什么（待确认再实施）

保持前台简洁，后台每条需求一张跟进卡：

- 规格、数量、地区、预算、期限及下次跟进日。
- 2–3 家候选供方和同规格报价、核实证据及有效期。
- 对接共享的接收方、用途、字段、同意时间和版本。
- 费用约定、成交/验收依据、交付/争议、实际收款记录。
- 明确的阶段：待核实、询价中、待同意对接、对接中、已成交、未成交、已结束。

现阶段可以先在私有运营表及现有内部备注中执行，不对外公开个人信息。不必立即建设支付、担保交易或复杂 CRM；真实重复工作出现后再结构化。

## 产品来源的边界

公开能抓到、有人愿意卖，并不等于有权供货。商业 API 集成自己的应用与转卖原始账号/Key 不是同一件事。OpenAI 商业协议允许 API 集成应用，但限制转售账号访问和 API Key 转让；Anthropic 商业条款允许面向用户的产品服务，对原始服务转售另有限制。[OpenAI 商业协议 2.2、3.1、3.3](https://openai.com/policies/services-agreement/)、[Anthropic 商业条款](https://www.anthropic.com/legal/commercial-terms)

平台合同违约与法律违法不能混为一谈，应逐案核对授权、账号归属、使用主体和地区。优先做可核验的正规采购协助、授权渠道和合规应用服务筛选，不协助规避地区、身份、支付限制。
