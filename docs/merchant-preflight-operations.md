# 店铺测试接入与审核

入口：`/admin/merchants` → 店铺申请详情。后台证明链接、店铺网址和商品样例链接在新标签页打开；不自动访问这些链接。

1. 新申请自动进入公开目录检测队列；初步检测不代替店铺归属或采集展示许可核验。
2. 想立即测试时，在申请详情点击“立即测试接入”，无需勾选审核确认或填写说明。Web 通过私有 Unix socket 唤起独立检测服务，不等下轮采集。
3. 页面显示“正在测试”，每 1.5 秒只读刷新这一块，保留正在填写的审核备注及勾选项，不自动批准。通常几秒到几十秒完成；90 秒未返回会停止轮询并提示核查。未安装或停止即时服务时明确提示，原自动队列仍保留。同一待测/进行中请求复用；刚检测完成的同店请求在 60 秒内显示最近结果，避免重复请求。自动采集仍约每 5 分钟一轮、最多测试 2 家；积压时会更久，请求 1 小时有效。
4. 查看有效报价数及最多 5 条样例，打开商品页人工核对价格、规格、库存说明。零有效报价、读取失败或待适配均不能批准。
5. 在“审核决定”按需填写审核说明（选填），确认归属、许可和样例，点击“确认批准”。留空也会记录审核人、时间、动作和确认项；仅在结果通知名额未使用时生成批准邮件。服务端仍要求当前申请版本的有效结果，检测完成后 24 小时内有效。
6. 正式采集仍按计划执行，只有符合网站展示规则的报价才显示；以后采集失败、库存变化等仍受公开报价过滤规则控制。“店铺已收录”不代表交易或售后保证。

未知系统需要站方适配，或店主提供**只读商品接口文档**。不要求店主提供后台密码、账号凭据或原始 API Key，也不绕过登录、验证码或访问限制。

## 失败原因与店主沟通

申请详情的 **接入测试** 展示已记录的具体原因和下一步。读取异常时显示“未读取成功”，不把错误分支的占位数字解释为店铺没有商品；只有实际读到目录才展示有效报价与原始解析数量。

每次申请最多两封自动邮件：提交回执一次，审核通过或明确无法接入的结果一次。接入失败需要店主协助时，第二封自动附原因及资料清单；发送后重测、更换邮箱和后续批准不追加第三封。检测进度、暂时服务故障和报价上线不额外通知。后台保留具体原因、下一步和「邮件通知」状态，不再展示复制文案和手动模板库。无邮箱需先补齐；SMTP 接受不等于保证进入收件箱。完整通知规则见 `docs/merchant-email-notifications.md`。

文案区分店铺安全校验、限流、登录要求、超时、DNS/TLS/网络、目录接口未找到、目录格式、平台待适配、无有效报价，以及需要站方排查的情况。接口返回 404 不等于店铺主页不存在；浏览器能打开不等于服务器能够读取公开商品目录。站方适配或服务问题不能写成要求店主修复其网站。

新版测试结果仅增加白名单原因码及可确认的状态信息，不保存原始异常正文、请求凭据或敏感响应。历史失败没有记录具体原因时，明确提示原因未记录，需要在获得授权后重新测试；不会追写或猜测历史失败原因。提示和模板以本地原因库 `lib/merchant-preflight-guidance.mjs` 为准。

## 权限及数据

- 私有 `submissions.sqlite` 的 `merchant_preflight_requests` 保存追加式请求审计。
- Web 仅写 `merchant-bridge/preflight-requests.json` 的脱敏请求，不写报价库、不直接联网抓店铺。
- Collector 仅在原有权限下读桥接清单，执行有界 HTTPS 目录探测，写 `data/merchant-preflights/MT-….json`。
- 即时服务使用相同的目录读取与过滤规则，仅接受已审计的 MT 请求编号，不能传入网址或命令。最多同时处理 2 个手动测试；忙碌时明确提示而非伪装成已开始。按请求加锁，避免与自动采集重复检测同一个请求；请求撤销或版本变化时丢弃进行中的结果。
- `/admin/merchants/:id/preflight` 仅供已登录后台只读刷新，不派发任务、不批准、不发信。手动 POST 保留登录、Origin、CSRF 和版本校验。脚本使用固定 CSP hash，网络仅限同源。
- 试采使用内存 SQLite 复用公开页面的过滤和去重，不写市场快照、告警或已批准店铺缓存。
- 结果读取限制 64 KiB，核对请求、店铺、版本、时间和同站商品 URL；仅返回允许的样例字段。
- 拒绝、暂停、批准等状态变更前先撤销旧试采授权；采集前后再次核对请求，旧版本结果不能用于批准。
- 启动时从私有请求审计重建未过期队列。私有数据库沿用现有备份；试采结果不是市场历史数据。

没有任何新增付费服务、自动购买或代收货款。供需撮合收费仍是独立的待确认方案。

## 即时服务部署

`deploy/price-radar-preflight.service` 使用 deploy 用户；`/run/price-radar-preflight` 为 0700，socket 为 0600，不监听 TCP 公网端口。只能写测试结果目录及自身运行目录，不能读取投稿数据库、统计库、备份或邮件凭据，桥接请求清单只读。

安装前先创建 `data/merchant-preflights`（deploy:deploy，0700），安装 unit 后 `systemctl enable --now price-radar-preflight`。更新共享 worker 时也要重启原 `price-radar-collect`，使两类进程都采用同一请求锁。常规部署及回滚已覆盖新 unit，未配置即时服务的旧部署会明确降级为自动队列，而不会声称立即测试。
