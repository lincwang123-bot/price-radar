# 店铺申请与审核

店主在 `/submit-shop` 提交公开店铺地址、主营品类、联系方式，并授权联系核验与公开目录采集。首次申请由站长在 `/admin/merchants` 人工核验店铺归属和采集权限；批准时必须分别确认两项，并填写可追溯的审核说明。联系方式和审核材料仅保存在私有申请数据库，不在公开页面展示。

批准后进入定时采集流程。适配器支持且采集成功后才展示有效报价；独立站等暂不支持的平台显示“待适配”，需要人工补充支持。审核通过不等于已经接入。店主已核验不是交易担保、API 直报或 Sponsor 广告背书。

暂停会撤下店主核验标识，并在下一采集周期移除动态采集目标；仅通过该动态接入产生的报价在该周期撤回。若店铺原本就在既有公开直采目录，其独立公开报价仍可保留。重新批准也需要核验确认和审核说明。

## 部署与运行数据

`MERCHANT_BRIDGE_DIR=/opt/linc/apps/price-radar/merchant-bridge` 同时写入应用 `.env`（采集服务）和 `/etc/price-radar/web.env`（网页服务）。部署脚本保留已有环境变量和凭据；若该配置已指向其他目录，部署失败并要求运维核对，避免意外扩大读写范围。不要打印环境文件。

桥接目录归 `deploy:deploy`，权限 `700`，其中清单应为 `600`。网页服务只额外获得该目录写权限，行情 `data` 仍只读；采集服务可读取桥接清单，但仍无法访问 `submissions`、`analytics` 和网页凭据文件。清单只能包含采集必要的公开店铺信息，不能包含联系方式和审核材料。

代码同步、代码备份及回滚均排除 `merchant-bridge`，运行中的清单不会被代码回滚覆盖。申请记录和审核日志随私有 `submissions` 数据库备份；恢复申请数据库后，网页服务启动时可重建桥接清单。桥接目录不是申请记录的备份源。
